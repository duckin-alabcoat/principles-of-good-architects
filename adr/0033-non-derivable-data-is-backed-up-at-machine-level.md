# ADR-0033: Non-derivable gitignored data is backed up at machine level

**Status:** Accepted
**Date:** 2026-07-02
**Deciders:** the operator (approved the recommendation surfaced in session 45); Federation Architect (drafted)

## Context

[ADR-0007](0007-github-as-system-storage-data-excluded.md) put the *system* in GitHub and excluded the *data* by `.gitignore`. The 2026-07-02 external consultant review (Auditor engagement per [ADR-0004](0004-auditor-as-separate-role-class.md), finding R4) surfaced the consequence that decision never addressed: the gitignored data is not all equally recoverable.

- **Re-derivable / re-pullable:** `inputs/` mirrors (re-copied from the live systems), `curate-runs/` staging (regenerated by `curate/gather.py`).
- **Non-derivable — exists nowhere but the local disk:** `users/<user-id>/` (the curated user profile + its append-only history), `architect-learnings.md` (the federation's own producer journal), and `proposed-edits/` (in-flight briefs and the receipt-ritual lifecycle record).

A drive failure loses the second set permanently. The same class exists in every participating Architect's repo (each has a gitignored `users/` copy, `architect-learnings.md`, and inbox).

## Decision

**The non-derivable gitignored data is left to a machine-level backup, not by any federation-owned mechanism.** Concretely:

1. POGA assumes each machine has a machine-level backup, and that backup **must include the portfolio's repo roots** — for the federation, its data root. Backing up the whole repo root trivially covers the gitignored subset; no path-picking needed.
2. **No federation-owned backup mechanism is built.** No second "data repo," no periodic tarball script, no sync job. The federation's storage boundary stays exactly as ADR-0007 drew it.
3. **Scope note for every Architect:** the same holds per system — a machine backup that includes each repo root covers every Architect's non-derivable data. Nothing to ship; this is a machine-level property, not substrate.

## Alternatives Considered

- **Private data-only git repo (or branch).** Rejected: re-introduces the data-in-git exposure ADR-0007 §"data out" exists to avoid (the user profile is preference/PII-adjacent), and adds a second sync ritual that will drift ([P16](../principles/master.md#p16--avoid-duplication) — a second authoritative-ish copy).
- **Federation-run periodic tarball/sync script.** Rejected: builds and maintains substrate to solve what one checkbox in a machine backup solves; another moving part with its own failure modes, and it still needs an off-machine destination — i.e., it *presupposes* the machine-level backup decision anyway.
- **Do nothing (status quo).** Rejected: the consultant's finding stands — the only copies of the user profile and the producer journal ride one disk.

## Consequences

- ADR-0007's "data excluded from GitHub" gains its missing complement: excluded from *git*, not from *backup*.
- The durability of the non-derivable data depends on a machine backup existing and including the repo roots. Setting that up belongs to whoever installs POGA on a machine, not to the federation.
- Nothing ships to Architects; no kit or substrate change. The federation records the policy so a future "should we build a data-sync?" conversation starts from a decided position.
