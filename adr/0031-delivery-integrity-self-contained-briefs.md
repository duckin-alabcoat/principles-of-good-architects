# ADR-0031: Delivery integrity — self-contained briefs and auto-pushed generated substrate

**Status:** Accepted
**Date:** 2026-06-21
**Deciders:** the operator, Federation Architect

## Context

[ADR-0027](0027-federation-delivers-edits-into-target-inboxes.md) gave the federation a working transport: it copies a proposed-edit brief into the target Architect's inbox over the shared volume, and the target's session-start sweep applies it ([ADR-0029](0029-receiving-architects-auto-adopt-at-startup.md) made that auto-adopt). The transport works. The **content** of the briefs did not.

Session 43 surfaced the defect when one member's Architect tried to apply its inbox brief. The brief told it to *"re-copy `CANON.md` from `bootstrap-kit/CANON.md`"* and *"copy `session.py` from the federation repo root."* Those paths exist only in the **federation's** filesystem. A brief is applied from the **target's** point of view, in the target's own repo — where neither `bootstrap-kit/` nor "the federation repo root" exists. So that Architect went hunting for files it could never find.

A review found the defect was not a one-off: **all four delivered briefs shared it**. Every one referenced `bootstrap-kit/...` and/or "the federation repo root" as the source for files the target was told to copy.

Two distinct things were conflated in those briefs:

- **Generated/identical substrate** — `CANON.md` (federation-generated by `distill.py`), `STANDARD.md` (federation-generated by `standardize.py`), and `session.py` (federation-root, byte-identical across every Architect). This is the federation's **own output**. Asking the target to *fetch* it is backwards — and points at a path the target can't see.
- **Genuine target edits** — wiring a guard into the target's `.claude/settings.json`, rewriting role-doc sections, bumping the version. These are real per-target work that belongs in a brief.

## Decision

Two rules, together "delivery integrity":

**1. Briefs are self-contained.** A brief references **only target-resolvable paths** — the target's own repo, or this brief's own inbox folder (`./payload/...`). It never references a federation-internal path (`bootstrap-kit/...`, "the federation repo root", etc.). Where a brief needs literal content, it **embeds** it (e.g. the exact hook JSON, the filled `session.config.json`); where it needs whole files the target lacks, it **delivers them as a `payload/` folder** inside the brief's inbox folder and references them inbox-relative (`./payload/CANON.md`). A pre-delivery guard, **`curate/check-brief.py`**, scans for the forbidden federation-internal substrings and fails before delivery — the [`add-structural-guard-on-recurrence`](../habits/master.md#add-structural-guard-on-recurrence) pattern ([P15](../principles/master.md#p15--code-for-mechanism-not-judgment)), since the defect recurred across all four briefs.

**2. Generated substrate is auto-pushed, not briefed.** The federation writes **and commits** its own `CANON.md` / `STANDARD.md` / `session.py` into every reachable converged repo via **`curate/push-substrate.py`** — no gate (the no-gate re-ship of generated canon/standard per [ADR-0022](0022-architect-ingest-distillation-and-code-channel.md) / [ADR-0024](0024-standard-role-doc-section-is-generated-and-injected.md)). This **refines ADR-0027's boundary**: ADR-0027 said the federation may write a target's *inbox* but never its *authored files*. ADR-0031 adds that the federation may also write+commit its **own generated substrate** anywhere it reaches — because the federation is that substrate's **single writer** (it is generated/identical-everywhere, not target-authored). It is still forbidden from writing a target's authored files (role doc, `session.config.json`, working files). The push **commits only the substrate paths** it changed (never `add -A` / `add .`), so it can never sweep a target's own uncommitted work into a commit. A converged repo (one carrying `CANON.md` + `session.py`) is detected by scan over the gitignored machine-local roots ([P3](../principles/master.md#p3--data-system-separation)); unconverged systems and the one custom-runtime member lack the markers and are skipped — they still get their substrate via their convergence brief's `payload/`.

The net: a brief carries only genuine target edits, and the generated substrate arrives by push. A target never hunts for a file it can't see.

## Alternatives Considered

- **A brief per substrate change (re-ship per file via a brief).** Churny, and exactly the path that produced the bug — it puts a fetch-from-federation instruction in front of the target.
- **Embed full file content of every substrate file in every brief.** Self-contained, but heavy: `session.py` is ~37 KB; every refresh would bloat every brief and duplicate the generator's output. Reserved for small literal fragments (hook JSON, config), not whole generated files.
- **A `session.py` harness change to auto-commit any dirty substrate at session start.** Rejected — it touches the core harness every Architect runs and would risk committing things it shouldn't. A path-scoped commit by a federation-only push script is simpler and leaves the harness alone.
- **Leave generated substrate as a target-fetch but fix the path.** There is no path the target can use — the federation repo isn't on the target's filesystem as a known location from the brief's POV. The fetch model is the wrong shape; push is correct.

## Consequences

- **The four briefs reduce to genuine target edits.** One wires a guard (embedded JSON); one is a pure audit/refresh; the two unconverged members install from scratch, but now carrying a `payload/` folder + embedded `session.config.json` instead of federation-path fetches.
- **The two converged members' substrate was refreshed live this session** by the push (their `CANON.md` / `STANDARD.md` / `session.py` were stale by bootstrap vintage).
- **The two unconverged members' briefs now carry payloads** — they are pre-convergence (no harness yet), so the push skips them and their files ride the brief.
- **Pairs with [ADR-0029](0029-receiving-architects-auto-adopt-at-startup.md):** auto-adopt only helps if the brief actually applies on arrival. These two ADRs together make a delivered change land without the target hunting or re-gating. (The convergence/install briefs are `Apply: manual` per ADR-0029's carve-out — surfaced for a working session.)
- **The ADR-0027 structural-guard candidate is partly realized:** ADR-0027 flagged "the federation should never write outside a target's inbox" as a future harness guard. The push script honors a refined version of that boundary in code (substrate-paths-only commit), and `check-brief.py` guards the inbox-content side.
- **`curate/push-substrate.py` and `curate/check-brief.py` are federation-only** — like `reconcile.py` / `distill.py`, not shipped to fresh Architects.
